# Event proposal boundary hardening - 26 October 2026

Scope: CF-24 proposal submission and assigned review plus CF-30 replacement safety. The proposal review vertical slice now has local shared-client and synthetic live-backend evidence; it is not institutional acceptance or production readiness.

## Implemented boundaries

- Create/edit resolve an active faculty/organizer from the current security context; a supplied user cannot impersonate another organizer. Editing resolves ownership before rendering even an invalid POST.
- Proposal editing is limited to PENDING/REJECTED records with no approval, cancellation, completion, operation workspace or registration history. Active events must use their separate reviewed lifecycle commands.
- Edits require the observed lifecycle revision. Resubmission clears the previous decision and advances the row version even when ordinary text is unchanged.
- Approval/rejection resolve a fresh administrator, prohibit self-review, lock the event and require the observed revision. Matching decision retries return without duplicating workspace, notification intent or audit; different/stale decisions fail.
- Create/edit/decision audit commits in the domain transaction. Failed audit rolls back domain changes and newly accepted uploads. Replacing a file does not physically delete the old committed asset; original immutable expiry/retention enforcement remains authoritative.
- Permanent event deletion is unavailable in service and is no longer offered as an active legacy button. Event history needs a separate reviewed archival/removal policy.
- Actual legacy forms carry revisions. Rejection is a visible ordinary POST form, independent of inline JavaScript. Invalid edit rendering includes speakers/sponsors. Denied MVC access returns a generic no-store 403; invalid lifecycle access returns a generic no-store 409.
- Service validation rejects empty normalized text, invalid intervals, nonfinite/negative fees, unbounded seats/text and malformed/unbounded contact email. Touched handlers do not return arbitrary exception details.

## Data, notification and recovery contract

Two nullable additive JPA fields record the last decision input revision and most recent proposal submission timestamp. Existing records have null decision metadata: they cannot claim a successful matching retry without provenance. No existing database or uploaded file was deleted. Production Mongo schema/migration and restore suppression remain separate release work.

Create/edit are private organizer commands; this slice adds atomic audit, not a new announcement trigger. Approval retains the existing bounded organizer/audience outbox and resumable campaign behavior. Rejection retains the existing organizer notification. Matching retries enqueue no extra messages. These are queued intents, not guaranteed device delivery. Create itself still lacks a durable idempotency receipt; an uncertain creation must be reconciled through the organizer list before another submission.

## Assigned review workflow added - 26 October 2026

Four nullable fields record reviewer ID, assigning administrator ID/time, and assignment input revision. Unassigned historical proposals fail closed: they must be explicitly assigned before any approval/rejection. An active administrator can assign an active administrator from a paginated directory; the organizer cannot review their own proposal. Only the current assignee can decide, even on an exact lost-response retry. Reassignment and approval serialize on the event row/version. Assignment records old/new reviewer IDs and revisions in private audit and sends a private inbox notice; it creates no workspace/public notice.

New no-store, bounded pages of 20 and typed DTO endpoints expose pending proposals and enabled administrator reviewers. The shared Event proposal review screen now supports assignment, complete key review fields, decision confirmation, rejection reason, paging, and uncertain-result recovery on web and Android source. It omits private media locators and shows whether uploads exist. Reviewers must inspect attachments through the authorized legacy event page; the shared screen does not display those files.

Approval changes the proposal to `APPROVED_PENDING_PUBLICATION`. It remains private: approved-only catalog, registration and volunteer queries do not admit this status, and approval creates no operations workspace or announcement. A separately revision-bound administrator publish command changes it to `APPROVED`, records publisher/time/revision, creates the workspace and queues bounded organizer/audience notices in the same transaction. Exact retries are no-write; stale revisions and invalid lifecycle state fail closed. Legacy MVC and the shared web/Android review screen expose separate approval and publication queues with explicit visibility confirmation.
