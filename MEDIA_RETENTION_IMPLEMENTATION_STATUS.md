## 19 October 2026: enclosing-transaction rollback compensation

The local-disk storage bridge now registers transaction completion for a newly written upload before saving its metadata. A confirmed enclosing rollback removes only that upload, guarded by the original filesystem identity, digest and real parent directory. Where the filesystem does not expose a file key (including the observed Windows provider), a private same-filesystem hard-link anchor verifies the original identity with `Files.isSameFile`; content equality alone is insufficient. Anchors are removed on completion and after repository-owned transactions. Unsupported identity tracking fails the upload instead of pretending rollback cleanup is supported. Commit retains the bytes. Unknown commit outcomes, changed/replaced objects and deletion failures preserve bytes and emit a reconciliation-required error; the callback does not sweep untracked paths, query or delete older assets, or change legal holds. The same guarded cleanup handles a synchronous metadata-save failure.

`MediaUploadTransactionPersistenceTest` adds seven real H2/JPA transaction scenarios for later enclosing failure, rollback-only completion, commit-preparation failure, successful commit/deadline preservation, repository-owned commit, changed contents and an identically populated replacement file, plus identity-anchor cleanup assertions. The initial run exposed three failed rollback assertions because null Windows file keys conservatively preserved bytes. The hard-link fallback addresses that actual failure; its coordinated rerun is pending, with no new pass claimed in this entry. Existing positive/negative media tests remain required. This is local filesystem/JPA evidence, not the target MongoDB/object-store acceptance.

Residual: abrupt JVM/OS loss before transaction-completion callbacks can leave orphan bytes and identity anchors, whose extra hard links can retain bytes even if the ordinary object path is later purged. Failed/ambiguous cleanup still requires a separately reviewed inventory/reconciliation workflow; the 30-day physical-purge guarantee is not established until this is addressed. Never delete unknown bytes automatically or infer their expiry from filesystem timestamps. A privileged local filesystem writer can race the identity check and deletion; production storage needs restrictive ownership/ACLs and isolated processing. Durable multi-store deletion proofs, encrypted private storage, derivatives/backups/restore suppression, scoped hold administration, parser isolation, quotas and measured purge lag remain production gates.
