# Proposal attachment backend — 30 October 2026

Scope: CF-24 private owner proposal operations and CF-30 uploaded-image retention. This is a local JPA/H2 slice, not Mongo, institutional identity, or production acceptance.

`POST /api/v1/organizer/event-proposals/{id}/attachments/{kind}` consumes multipart `file`, `expectedRevision`, `requestKey` (UUID). Kind is `banner` or `certificate-template`. Response is a no-store/private receipt: `id`, `revision`, `kind`, `uploadAcceptedAt`, `expiresAt`, `replayed`. No object key is returned.

The service locks MODULE_EVENTS policy, refreshes/locks the active FACULTY/ORGANIZER account, locks the owned event, and delegates pure PENDING/REJECTED editing to the existing EventService command. Existing image sanitization, bounded parsing, atomic audit, rollback cleanup, and separate private banner/template bindings are reused. Successful replacement resets reviewer assignment and prior decision, returns the proposal to PENDING, and advances its revision. Existing media bytes/metadata retain their original expiry until retention purges them.

Owner/request-key receipts use a length-delimited command fingerprint and bounded original upload digest. Matching retry returns the original receipt without a second upload or expiry reset. A changed payload/key pairing conflicts. New request keys cannot renew identical sanitized content: canonical image SHA-256 is checked against the current binding, all prior owner/event/kind media metadata, and durable attachment receipts. The history check includes non-current legacy uploads without attachment receipts. Conflict rolls back newly staged bytes, metadata, event changes, and audit. This protection does not establish a university-wide owner quota across separate events; broader upload quotas remain a release task.

The additive JPA receipt table requires reviewed production migration; no production database was changed. Retained content hashes/receipt metadata need the institution's non-file-record retention policy. Deployed Mongo concurrency, physical recovery/purge proof, installed Android upload behavior, and external assessment remain open.
